# Early-Exit Optimization Study — Implementation and Run Specification

## 0. Purpose

This document defines a new **two-stage early-exit (EE) optimization study** aligned with the current `main` branch of `MuhammadSufyanHaider01/Hierarchical-MultiScaleJEPA`.

The study compares three EE head-training algorithms using the same frozen ViT-pretrained P0 and P2 checkpoints for the M-block masking condition (`multi_block_n6`):

1. **Current EE** — existing frozen single-exit head in `main`.
2. **Causal Fusion EE** — Stage 1; each exit fuses all representations already computed up to that depth.
3. **Fusion-Teacher Distillation EE** — Stage 2; an ordinary single-representation exit head is trained from the corresponding Stage-1 fusion head at the same depth.

The study is intended to answer two questions:

- **Performance:** can better downstream head training increase performance at earlier exits?
- **Stability:** after improving the heads, does the same task show a clearer and more reproducible best exit across downstream head seeds?

The pretrained encoder, downstream split, task metrics, and validation-only exit-selection rule must remain fixed so that gains can be attributed to the EE head-training algorithm.

# 6. Stage 1 — Causal Fusion EE

## 6.1 Goal

The current EE head sees only the representation at the target exit, \(Z_k\).

Stage 1 asks:

> If inference has already computed earlier representations while reaching depth \(k\), can the task head achieve better performance by using those representations as well?

The encoder remains frozen and unchanged.

Fusion is performed only in the downstream head. It is a **skip-to-head** mechanism, not a skip/residual connection inside the ViT encoder.

## 6.2 Causal source layers

For target exit \(k\):

\[
\mathcal J_k = \{j \in \{2,4,6,8\}: j \le k\}
\]

Therefore:

```text
L2 ← L2
L4 ← L2 + L4
L6 ← L2 + L4 + L6
L8 ← L2 + L4 + L6 + L8
```

A target exit may never consume a deeper representation.

## 6.3 Multi-layer encoder API

Do not obtain L2/L4/L6 for an L6 fusion head by calling `forward_to_layer` three times. That would recompute the encoder prefix.

Add a public helper in `src/models/encoder.py` around the existing `_forward_layers(...)`:

```python
def forward_to_layers(self, x, exit_layers):
    return self._forward_layers(
        x,
        masks=None,
        return_layers=exit_layers,
        normalize_exits=True,
        stop_at_last_requested=True,
    )
```

For:

```python
exit_layers = [2, 4, 6]
```

the encoder must execute blocks 1–6 once and return `Z2`, `Z4`, and `Z6`.

Blocks 7–8 must not execute.

## 6.4 Pooling

For each source layer:

\[
Z_j \in \mathbb{R}^{B 	imes N_j 	imes D}
\]

Mean-pool exactly like the existing EE head:

\[
u_j = rac{1}{N_j}\sum_{n=1}^{N_j} Z_{j,n}
\]

where \(N_j\) is the token count at that exit, **not the number of random seeds**.

For the current ViT:

```text
D = 256
```

## 6.5 Trainable fusion weights

For each target exit \(k\), create trainable scalar logits:

\[
a_{k,j}, \quad j \in \mathcal J_k
\]

Normalize them:

\[
lpha_{k,j}
=
rac{\exp(a_{k,j})}
{\sum_{m\in\mathcal J_k}\exp(a_{k,m})}
\]

so:

\[
lpha_{k,j} \ge 0,
\qquad
\sum_j lpha_{k,j}=1.
\]

Fuse:

\[
	ilde u_k
=
\sum_{j\in\mathcal J_k}
lpha_{k,j}u_j.
\]

Then keep the current downstream head form:

\[
	ilde u_k

ightarrow
\mathrm{LayerNorm}(256)

ightarrow
\mathrm{Linear}(256,C_t).
\]

## 6.6 Initialization

Initialize all fusion logits to zero:

\[
a_{k,j}=0.
\]

Thus initial fusion is uniform:

```text
L4: [0.5, 0.5]
L6: [1/3, 1/3, 1/3]
L8: [0.25, 0.25, 0.25, 0.25]
```

For L2:

\[
	ilde u_2 = u_2
\]

and no redundant fusion parameter is needed.

## 6.7 New classes

Extend:

```text
src/models/exit_heads.py
```

without modifying the existing baseline classes.

Recommended new classes:

```python
class CausalFusionExitHead(nn.Module):
    ...
```

```python
class FrozenEncoderFusionExit(nn.Module):
    ...
```

`CausalFusionExitHead` should:

- receive a `{layer: tokens}` mapping;
- validate `[B,N,D]` tensors;
- mean-pool each source;
- softmax the fusion logits;
- compute the weighted sum;
- apply LayerNorm;
- apply the task projection;
- expose normalized fusion weights for logging.

`FrozenEncoderFusionExit` should:

- determine causal source layers;
- freeze the encoder;
- keep it in `.eval()`;
- call `encoder.forward_to_layers(...)` under `torch.no_grad()`;
- pass the returned representations to the fusion head.

# 7. Stage 2 — Fusion-Teacher Distillation EE

## 7.1 Goal

Stage 2 asks:

> Can the performance knowledge learned by a multi-representation fusion head be compressed into the original lightweight single-representation EE head?

## 7.2 Same-depth teacher rule

Use the corresponding Stage-1 fusion head at the same depth:

```text
Fusion L2 → Student L2
Fusion L4 → Student L4
Fusion L6 → Student L6
Fusion L8 → Student L8
```

Examples:

\[
H_4^F(Z_2,Z_4)

ightarrow
H_4^S(Z_4)
\]

\[
H_6^F(Z_2,Z_4,Z_6)

ightarrow
H_6^S(Z_6).
\]

Do not use L8 as a universal teacher in this first experiment.

Cross-depth distillation is a separate future ablation.

## 7.3 Student architecture

The Stage-2 student must be the current baseline head:

```text
Zk
↓
MeanPool
↓
LayerNorm
↓
Linear
↓
prediction
```

The student must not require earlier representations at inference.

## 7.4 Teacher identity

The teacher must match the student in all of:

```text
pretraining method
pretrained checkpoint
head seed
task
exit layer
split manifest
```

Example:

```text
P2 / head_seed_003 / rfs / L6 student
```

must use:

```text
P2 / head_seed_003 / rfs / L6 fusion teacher
```

Teacher SHA256 must be recorded.

## 7.5 Frozen components

During Stage 2:

```text
encoder = frozen
fusion teacher = frozen
student head = trainable
```

Teacher and encoder computations occur under `torch.no_grad()`.

Only student parameters are passed to the optimizer.

## 7.6 Classification KD

Teacher logits:

\[
z_k^F
\]

Student logits:

\[
z_k^S
\]

Temperature-scaled teacher:

\[
q_k
=
\mathrm{softmax}(z_k^F/T)
\]

Temperature-scaled student:

\[
p_k
=
\mathrm{softmax}(z_k^S/T)
\]

Task loss:

\[
\mathcal L_{task}
=
CE(z_k^S,y)
\]

KD loss:

\[
\mathcal L_{KD}
=
T^2 KL(q_k \parallel p_k)
\]

Total:

\[
\mathcal L
=
(1-\lambda)\mathcal L_{task}
+
\lambda\mathcal L_{KD}.
\]

Initial fixed settings for the first formal run:

```text
T = 2.0
lambda = 0.5
```

Expose:

```text
--kd-temperature
--kd-weight
```

but do not tune them by task for the initial study.

## 7.7 NR positioning KD

For `nrpos-outdoor`, use prediction-space distillation.

Teacher output:

\[
\hat y_k^F
\]

Student output:

\[
\hat y_k^S
\]

Task loss:

\[
\mathcal L_{task}
=
MSE(\hat y_k^S,y)
\]

KD loss:

\[
\mathcal L_{KD}
=
MSE(\hat y_k^S,\hat y_k^F)
\]

Total:

\[
\mathcal L
=
(1-\lambda)MSE(\hat y_k^S,y)
+
\lambda MSE(\hat y_k^S,\hat y_k^F).
\]

Compute this in the same normalized coordinate space used by the current training code.

Validation/test reporting remains physical `mean_distance_error`.

## 7.8 Student initialization

For the first formal comparison, initialize the Stage-2 student from scratch with the same deterministic head seed protocol as Current EE.

Do not initialize from:

- the fusion teacher;
- a trained Current EE head.

This keeps the training budgets comparable:

```text
Current EE: max 200 epochs
Fusion EE: max 200 epochs
Fusion-KD EE: max 200 epochs
```

A later ablation can study baseline-initialized KD fine-tuning.

## 7.9 Stage-2 runner

Add:

```text
scripts/phase5_fusion_distill.py
```

Reuse Phase-5 data/split/evaluation utilities.

Add required arguments:

```text
--fusion-teacher-root
--kd-temperature
--kd-weight
```

The script must resolve and validate the same-depth teacher before training.

## 7.10 Run Stage 2 for all exits

Do not gate Stage 2 only on fusion accuracy improvement.

A fusion teacher that is close in hard-label metric may still provide useful soft prediction structure.

Instead, record teacher improvement relative to Current EE and analyze whether KD gains correlate with it.

Direction-normalized teacher improvement:

Classification:

\[
G_k^F = M_k^{fusion,val} - M_k^{current,val}
\]

Positioning:

\[
G_k^F = M_k^{current,val} - M_k^{fusion,val}
\]

so positive always means improvement.

# 19. Direction-aware gains

Use a unified positive-is-better delta.

Classification:

\[
\Delta_{new,current}
=
A_{new}-A_{current}
\]

Positioning:

\[
\Delta_{new,current}
=
E_{current}-E_{new}
\]

Therefore:

```text
positive = improvement
negative = degradation
```

Use this convention in combined plots.

# 27. Scientific interpretation

### Current EE

Tests:

> How useful is the representation exactly at depth \(k\)?

\[
Z_k 
ightarrow H_k.
\]

### Causal Fusion EE

Tests:

> How useful is all information already computed by depth \(k\)?

\[
(Z_2,\ldots,Z_k) 
ightarrow H_k^F.
\]

### Fusion-Teacher KD EE

Tests:

> Can the information benefit learned by the fusion head be compressed back into the original single-depth exit?

\[
H_k^F(Z_{\le k})

ightarrow
H_k^S(Z_k).
\]

# 28. Deployment interpretation

At selected exit Lk:

### Current EE

```text
ViT blocks 1..k
→ current lightweight head
```

### Causal Fusion EE

```text
ViT blocks 1..k
→ causal intermediate taps
→ pool each tap
→ learned alpha fusion
→ LayerNorm + Linear
```

### Fusion-Teacher KD EE

```text
ViT blocks 1..k
→ original-style lightweight head
```

The fusion teacher disappears after training.

If Fusion-KD retains a meaningful portion of Fusion performance, it is especially attractive because deployment returns to the original lightweight EE head structure.

---

# 29. Success criteria

The experiment is promising if one or more of the following occurs consistently:

1. Fusion improves earlier exits over Current EE.
2. Fusion-KD retains or improves the Fusion gain.
3. An earlier Fusion/Fusion-KD exit matches or exceeds a later Current EE exit.
4. The validation-selected exit becomes more concentrated on one depth across the seven head seeds.
5. Selected performance improves without meaningful deployment-compute increase.
6. P2 benefits more strongly than P0, indicating synergy between hierarchical pretraining and hierarchical downstream fusion.
7. Learned alpha values reveal consistent task-specific use of earlier vs current representations.

Neutral or negative results should also be retained because they help distinguish a representation limitation from a head-training limitation.
